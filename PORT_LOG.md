# Port log: Isabelle2025 → Isabelle2026-RC0

What was changed in this fork, why, and how each change was checked.
Written for the original authors, so it states findings rather than
assuming familiarity with the fork.

Upstream: `ultra-group/isabelle-gst`. This fork: `newsniper-org/isabelle-gst`.
Environment: Isabelle2026-RC0, `ZFC_in_HOL` from a clean AFP checkout,
Poly/ML 5.9.2, TeX Live 2026.

Commits, oldest first: `369b2e3`, `8b5f791`, `14027ec`, `a9f134e`, `a66cf94`.

---

## 1. The port itself (`369b2e3`)

Three independent breakages. `isabelle build -D src GST` is green again.

**Mixfix templates now carry nested-cartouche markup** (`notation=` /
`indent=` / `open_block` hints). A `no_notation` or `no_syntax` whose
template does not match EXACTLY is **silently ignored** — so every removal
in `src/remove_syntax.thy` had quietly become a no-op. The first visible
symptom was `Soft_Types.thy:48` failing to parse: the soft-type notation
`x : P` was ambiguous against `Set.member`'s ASCII `:`, because the removal
meant to hide it no longer matched.

Verified in both directions with a minimal probe theory: the old string
template leaves `:` ambiguous, the current one removes it. Every removal is
now copied verbatim from the current library source, and where the library
offers a declaration bundle, `unbundle no X_syntax` is used instead — that
form survives future template changes, which is what `isabelle/NEWS`
recommends. Three bundles apply: `member_ASCII_syntax`,
`set_enumeration_syntax`, `funcset_syntax`.

**`YXML.content_of` no longer accepts a raw string.** In
`ModelKit/Tools/lift_model_sig.ML` it now goes through
`XML.content_of (YXML.parse_body …)`.

**Morphisms need an explicit context.** `Tools/locale_tools.ML`'s
`interp_morphism` now does `Morphism.set_context' ctxt (snd reg)`.

## 2. ROOT named only one theory (`8b5f791`)

`ROOT` listed `Founder/Test` alone, so **any theory nothing imports was
never built, and therefore never checked**. Naming the leaves as well
raised the session from 54 to 57 theories, which is all of them.

Three leaves were real and build clean once named: `GZF/Successor`,
`Functions/FunctionSpace`, `Ordinal/DependentOrd`.

Widening ROOT is what exposed four dead files, each a leftover from a
rename or move whose old copy was never deleted. A clean rebuild after
removing all four is green at the same 57 theories, which is the check
that they were dead. One of them (`Ordinal/Model/mSucc.thy` vs `msucc.thy`)
was worse than dead: Isabelle refused the session outright as a
case-insensitivity collision, and it could not compile anyway — its
`context Ordinal_Model` is closed immediately, leaving the lemmas outside
the context they need.

## 3. The paper's example GSTs (`14027ec`, `a9f134e`)

`todo` asks for "Examples from paper: ZF, ZFP, ZFO, ZFN, ZF+" — figure 4 of
the CICM 2021 paper, which numbers the features 1 = Set, 3 = Pair,
5 = Nat, 7 = Exception. **"ZFO" appears to be a slip for ZFE**: the figure
has no ordinal GST. Only ZF+ existed here; the other four are new, in
`Founder/GST_Examples.thy`:

| | features | extra axioms |
|---|---|---|
| `ZF` | Set | `Iden(1)` — so everything is a set |
| `ZFP` | Set + Pair | `AllDistinct(1,3)` |
| `ZFN` | Set + Nat | `AllDistinct(1,5)` |
| `ZFE` | Set + Exception | `AllDistinct(1,7)` + `ExOutside(1)` |
| `ZFplus21` | Set + Pair + Nat + Exc | `AllDistinct(1,3,5,7)` + `ExOutside(1,5)` |

Each is generated by `mk_gst` from its feature list, so this is also the
first exercise of that generator beyond the single existing call.

**Two different ZF+.** The 2022 paper reuses the name for sets + ordinals +
pairs + functions + exception, which is the existing `ZFplus` class and the
one `Test` builds a model for. Both are kept; the 2021 combination is the
new class `ZFplus21`, and the theory header explains the split.

`a9f134e` adds the "everything is distinct" GST. `todo` lists it under
"interesting choices" rather than as a paper example, **so the reading is
ours** and is stated in the theory: every feature present at once with all
their objects kept apart — the largest `AllDistinct` this development can
state (GZF, Ordinal, OrdRec, OPair, BinRel, Function, Nat, Exc). `Exc` is
blacklisted for exactly the four features with a real cargo and not for
those whose cargo is `top`, for the reason already recorded for `Nat`:
blacklisting against a `top` cargo asserts `Exc = bot` and the class turns
vacuous.

Writing it surfaced a typo that had been invisible: `GST_Features.thy`
declared the ordinal-recursion feature record as `val OrdReec` (two e's).
Nothing referenced it — `ZFPlus_spec` uses `Ordinal` but not `OrdRec` — so
no build had ever failed on it. This is the first spec to name the feature,
which is what caught it.

## 4. The document builds (`a66cf94`)

`isabelle build -o document=pdf` failed with 78 LaTeX errors; it now
produces **238 pages with none**. Five defects, all one class: a document
comment is TEXT, handed to LaTeX as written, and only an antiquotation goes
through symbol translation. A section title is worse still, because
hyperref repeats it in the PDF bookmark.

- `ModelKit/Tagging.thy` uses `\<^enum>` as the mixfix of `Part`. That
  symbol is `group: document` (`etc/symbols`, code `0x25b8`) — meant for
  list markup inside comments. Inside a TERM it goes out as
  `\isactrlenum`, which nothing defines: not in Isabelle's `lib/texinputs`
  (the only place `isabelle.sty` lives — the system TeX Live has no
  `isabelle*.sty` at all), not anywhere in the Isabelle2026-RC0 tree.
  `document/root.tex` now defines it with the glyph the symbol table
  assigns. **49 of the 78 errors.**
- `GZF/UPair.thy`, `Ordinal/Ordinal.thy`: bare `\<P>`, `\<emptyset>`,
  `\<omega>` in section titles → now `\<^term>` antiquotations.
- `GZF/SetComprehension.thy`: bare `\<lambda>` in a `text` block.
- `Founder/ZFC_in_HOL_Bootstrap.thy`: `ZFC_in_HOL` as prose — `_` is
  math-mode-only in LaTeX → now `\<^verbatim>`.
- `GZF/EmptySet.thy`: `&` in a section title — LaTeX's alignment tab.

Reproduce with `isabelle build -D src -c -o document=pdf GST`. The `-c`
matters: a cached session otherwise reports success in four seconds without
running LaTeX at all.
